Avatars that watch your cursor

Geometric 3D characters in plain SVG, generated from any string you already have. Zero dependencies, no build step, and an editor your users can drive.

Deterministic

Any string is already an avatar

An email, a user id, an agent name. The same seed gives the same character every time, on every machine, for ever — so you can compute it at render time instead of storing it.

Cheap at scale

Thirty of them cost one pointer read

Every avatar on a page shares one pointermove listener and one requestAnimationFrame loop. The loop parks itself for a hidden tab, an off-screen element, or prefers-reduced-motion.

—fps —live avatars 1rAF loop 1listener

The editor, in one function call

Build a character, then take it with you

This is mountEditor() — the whole thing, framework-free, the same call you would make in your own app. Export it as SVG or PNG, or copy a link that reopens exactly what you made.

Everything here is the published package running in your browser. Nothing is uploaded, and nothing is stored — a character is a JSON document that fits in a URL.

Install

Three lines to the same place

Pick whichever fits your stack. They ship identical code.

npm

ESM, with TypeScript declarations in the box.

$ npm i avatarkit

import { createAvatar, generateScene }
  from "avatarkit";

createAvatar("#slot",
  generateScene(user.email));

A script tag

No toolchain at all. One file, one global.

<script src="https://unpkg.com/avatarkit"></script>

<script>
  Avatarkit.createAvatar("#slot",
    Avatarkit.generateScene("hello"));
</script>

React, Vue, anything

No wrapper package. A ref and an effect is the whole integration.

useEffect(() => {
  const a = createAvatar(ref.current,
    generateScene(seed));
  return () => a.destroy();
}, [seed]);

On a server, or in a list

No DOM needed. A string the browser caches as an image.

const svg = renderToString(doc, {
  size: 48,
  idPrefix: "u1",
});

How it works

Convex solids, not a mesh

1

Primitives

Spheres, capsules, rounded boxes, cones and wedges — each with a position, a size, a depth and three rotations. Concave characters are built by stacking convex parts, which is also the only vocabulary the editor exposes.

2

Hulls

Every frame, each part's surface points are rotated, projected through a pinhole camera, and reduced to a convex hull — the exact silhouette of a convex solid under any projection. No triangles, no WebGL.

3

Seams

Hulls are painted back to front, fill then outline, so a nearer part's outline lands across a farther part's fill. That seam is the whole visual signature — it is what makes a cat read as a head with ears behind it.
